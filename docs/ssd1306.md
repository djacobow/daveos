# SSD1306 display

Select `ssd1306` in the STM32 example's Meson `features` list. It adds the
`display` transfer module, the 1 Hz `debug_display` renderer, and shared `i2c scan`, `i2c stats`, and `i2c reset` commands.
The feature is optional and independent of networking, storage and the ADC.
When selected together with `i2c-adc`, both clients share one bus owner and IRQs.

The Nucleo fixture is a 128×64 SSD1306 on I2C1: PB8 SCL, PB9 SDA, seven-bit
address 0x3c, common ground and suitable pull-ups. It uses the internal charge
pump and has no reset GPIO. Both boards select the 64 MHz HSI clock and the
same conservative timing (below 100 kHz). Configuration is in
`examples/stm32_console/i2c_probe.hpp`; family aliases are in each board's
`i2c_board.h`. At the first 1 Hz tick, the example attempts initialization.
If that succeeds, subsequent ticks render the status view. An absent panel or
failed initialization silently disables automatic updates: no log spam and no
background retry. Explicit `display live on` requests another attempt.

```text
display live off
i2c scan
display init
display text "DaveOS H755"
display pattern
display clear
display live on
i2c stats
```

`display text` clears the screen and draws a single ASCII line at the top left
(up to 21 characters in the included 6×8 font). Quote strings containing spaces.
`display pattern` draws a checkerboard with an outer border. Successful writes
log `SSD1306 update complete`; this confirms I2C completion, not visible pixels.
Manual init/text/pattern/clear commands pause the status view. Use
`display live on` to resume, or `display live off` to leave the last image in
place. Pausing does not cancel an accepted transfer; it finishes normally.
Automatic updates are quiet on success and failure. Explicit commands retain
completion/error logging. MCU reset restores the default automatic mode.

## Status view

| Row | Content |
| --- | --- |
| 1 | Uptime in days and hh:mm:ss |
| 2–6 | Five application-supplied ASCII rows |
| 7 | Serial number, or `SN:(none)` |
| 8 | Firmware major.minor.build, or major.minor `local` |

The example supplies board name and Git revision in the middle rows and leaves
the other rows blank. It does not invent a serial number when none is supplied.
Rows are limited to 21 characters; callback output is terminated and clipped,
with nonprintable/non-ASCII bytes replaced by `?`. The serial payload has 18
characters after its prefix. Long version strings are clipped to the row width.

`drivers/debug_display.hpp` provides `DebugDisplay<Platform, Target, Event>`.
Inject the clock/platform, a target with `live()` and `show(DisplayLines)`, a
version value, and an optional `DisplayContent` callback. Callback indices 0–4
fill the middle rows; index 5 supplies the serial string. Its output span is
borrowed only for the callback. No provider runs during construction/init.
The example provider lives in `examples/stm32_console/debug_display.hpp`.

`drivers/adapters/ssd1306.hpp` provides `Ssd1306Module<Bus, Event>`, the target
that owns the driver, borrows the bus lease and exposes manual commands. Its
1 ms task advances transfers; the separate renderer's task runs at **1 Hz**.
Busy frames are skipped rather than queued. Each accepted refresh sends all
eight pages (no duplicate framebuffer or changed-page cache). A failed automatic
transfer disables live mode silently and releases the lease. This separates
presentation cadence from asynchronous I2C progress.

## Reusable driver

`drivers/ssd1306.h` provides `daveos::drivers::Ssd1306`, independent of STM32,
logging and the scheduler. Inject a `hal::i2c::Device` for the desired address.
Construction is passive. `initialize()` requests initialization and a clear;
`fill()`, `pixel()`, and `text()` edit the owned framebuffer; `refresh()` submits
it. Call `tick()` cooperatively and inspect `result()` after `busy()` clears.

The driver uses a 1,024-byte framebuffer and a 129-byte transmit staging buffer.
It sends an address command and one page per pair of asynchronous transactions.
The display stays off until initialization has cleared every page. All writes,
including initialization, check completion. Drawing and new requests are
rejected while busy. Borrowed transfer buffers remain alive and unchanged until
the HAL completes, including timeout. There is no retry or cancellation.

The driver uses the shared CRTP state-machine helper. Applications must keep the
driver and its device alive until it is no longer busy. The example retains a
bus lease throughout each update so scan/reset cannot interrupt it. Errors
release the lease; only explicit commands log them; explicitly reset a faulted bus with `i2c reset`,
then use `display init`. A controller reset does not reset the panel itself.

The initialization sequence and font were adapted from a fork of
`afiskon/stm32-ssd1306`. Its MIT notice is preserved in
`lib/drivers/ssd1306_LICENSE`. Only the required 6×8 font is included.

## Validation

Host tests cover initialization/page ordering, clear-before-enable, framebuffer
layout, ASCII/bounds checks, buffer retention, rejected requests, failure at
initialization/address/data/enable stages, and explicit retry after failure.
Physical ACKs do not verify orientation or image quality; those require visual
confirmation. Read transactions, repeated START, and intentional stuck-bus or
clock-stretching tests are outside this display fixture's coverage.

ASan/UBSan passed 44/44 and fake/no-logging passed 38/38; both H563/H755 A/B
firmware builds passed. H755 hardware ACKed 0x3c and completed initialization
and text/pattern/clear writes. The final HIL check synchronizes on command
echoes before completion and checks exact transfer counters, avoiding stale
completion logs broadcast from another console. H563 was not flashed for this
change. On 2026-09-23 the user visually confirmed the OLED displays
"DaveOS H755". Test-pattern pixels and screen-edge coverage have not yet been
visually checked.

The automatic status-view H755 HIL run passed factory startup, pause, all 258
manual display writes, and live-mode resumption: counters held at 340 while
paused, then rose to 404 after four complete 1 Hz frames, with no new errors
or timeouts. Watchdog/fault checks passed. The display was left in automatic
mode. Host tests cover silent NACK both during initialization and after a
successful initialization, no background retries, lease release, bounded row
formatting, and the 1 Hz task descriptor. Physical panel removal was not tested.
H563 builds include both ADC and display to check shared-bus composition; H563
was not flashed. The earlier visual confirmation was for static text; this
new status layout has not yet been visually inspected.
